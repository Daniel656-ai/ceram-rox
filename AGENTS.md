- Nachträgliche Änderungen an Auftraggeber-Vorgaben (measurement_parameters) laufen nur über die Datenbankfunktion amend_order_spec, die Wert und activity_log-Eintrag (order_spec_updated) atomar schreibt — Historie darf nie fehlen; Messdienstleister haben nur Lesezugriff.
- External-customer data isolation is enforced only via RESTRICTIVE SELECT policies gated by `is_external_customer()` / `external_owns_sample()`; never loosen or bypass them, and add a matching restrictive policy when a new table exposes order/sample/result data — keeps internal permissive policies untouched while external users stay limited to their own orders.
- Assignment changes of order_measurements go only through SECURITY DEFINER RPCs (claim_measurement, release_measurement, reassign_measurement — NULL target removes the assignment with mandatory reason) that lock the row and log to activity_log; a trigger rejects direct assigned_to updates by app roles — keeps competence, status and audit checks server-side.
- Numeric production-release fields are parsed only via `analyzeDimensionText` (`src/lib/productionRelease/dimensions.ts`); multi-dimension/ambiguous text is never collapsed into one number, goes to review, and its original text is kept in `field_sources[key].raw` — prevents silent corruption like "152 x 152" → 152152 without a schema change.
- M3 order labels are projected only at the shared form's rendering boundary in `src/lib/m3List/orderDisplay.ts`; persistence, exports, handover and calculations retain original derived values — isolates presentation from business data.
